# das-cli Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the DAS CLI that converts documentation sources (GitHub URL, file, folder, project root) into progressive-disclosure Claude Code skills with pin-and-check refresh, per the approved spec at `docs/superpowers/specs/2026-07-22-das-design.md`.

**Architecture:** A pure-core, effectful-shell design. Parsing, tree building, sizing, emission planning, slug/ordering logic, and the injection scan are pure functions over in-memory values (fast, exhaustively unit-testable). Filesystem, git, locking, and the CLI wrap that core. The slicer produces a `SkillPlan` (a list of file paths and contents) that the emitter writes via transactional swap.

**Tech Stack:** TypeScript (strict, ESM), Node >= 20, pnpm, Commander, Inquirer (`@inquirer/prompts`), Chalk, zod, vitest. Same conventions as `~/projects/cpm-cli/`.

## Global Constraints

- **Spec is authoritative:** `docs/superpowers/specs/2026-07-22-das-design.md`. Every behavior cited below (budgets, hardening flags, validation rules) is copied from it; on conflict, the spec wins.
- **TDD, strictly:** write the failing test, watch it fail, implement minimally, watch it pass, commit. Never delete a failing test; fix the code.
- **TSDoc only:** every exported symbol gets a TSDoc block (`@param`, `@returns`, `@throws` where relevant). No inline comments anywhere in function bodies. Comments explain constraints, never restate code.
- **Naming:** descriptive variable names; no single-letter or abbreviated names (conventional `i`, `id`, `err` allowed).
- **DRY:** shared logic lives in one module; tasks name the module to reuse. No copy-pasted helpers.
- **Token budget default:** 4000. Estimation: `chars / 4` prose, `chars / 3` fenced-code content.
- **Security invariants (always):** symlinks never followed; every output path `path.resolve`d and prefix-checked inside the skill dir; git spawned as argument vectors with `--` separator, never a shell; clone env/flags exactly as speced.
- **Git workflow:** one branch per phase (named below), conventional commits per task, PR per phase referencing its GitHub issues (`Closes #N`), CI (typecheck + lint + test) green before merge.
- **Commit trailer:** end every commit body with `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.
