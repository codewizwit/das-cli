Properties of the emitted bytes, so every number here is deterministic and costs nothing
to reproduce. Instrument and corpus are in [`METHOD.md`](METHOD.md). Generated by
[`instrument/analyze.mjs`](instrument/analyze.mjs).

| | before, 0.2.0 (`dd11bca`) | after (`1688c38`) |
| --- | --- | --- |
| resources emitted | 93 | **98** |
| generated indexes | 10 | **20** |
| max tree depth | 5 | **4** |
| resource body byte-identical to its source | **0/98** | **98/98** |
| sentence coverage of source prose | 97.8%, 87/98 files intact | **100%, 98/98** |
| authored `description` carried into an index entry | **8/98** | **98/98** |
| `SKILL.md` | 306 est. tokens, no navigation guidance | 852 est. tokens, explicit routing rules |
| untrusted-content notice placed above das's own generated table of contents | yes | scoped out of `SKILL.md` |
| index share of total skill tokens | 4.0% | 4.7% |

Token counts use das's own `estimateTokens` (4 chars per token for prose, 3 inside a
fence), replicated in the analysis script so the figures are comparable to the est. token
columns in the earlier evaluations.

**Byte fidelity is measured on the body.** Every emitted resource carries a one-line
untrusted-content frame by design, so no emitted file is ever raw-identical to its source.
The 98/98 is the body underneath that frame.

**Sentence coverage** counts sentences of 40 or more characters present verbatim in the
emitted tree after whitespace normalisation, so it survives re-wrapping, heading-level
changes and blank-line normalisation. The 0.2.0 build dropped 64 of 2,890 sentences across
11 files, worst case `writing/code-and-readmes.md` at 71%. No file was lost entirely.

An earlier attempt to measure this by searching for each file's longest prose line
reported 71 files affected and 5 lost outright. That metric was wrong: it broke on
re-wrapping rather than on missing content. The sentence-coverage figure supersedes it.

## The index entry, which is the part a reader can judge without numbers

Before, from the root `SKILL.md`:

```
- [architecture](resources/architecture.md)
- [brand](resources/brand/index.md)
- [wizwit knowledge](resources/wizwit-knowledge.md) — Everything wizwit knows, in markdown, one fact in one place. Twelve sections, each with a README saying what belongs in
```

Ten of thirteen root entries carried no description. The three that had one were cut
mid-sentence at 120 characters.

After:

```
- [Architecture](resources/architecture/_das-index.md) — How this corpus governs itself: the frontmatter contract, precedence, the gates, and what das owns. Contains: What das owns; Frontmatter in this corpus; The gates; Precedence.
- [Evidence](resources/evidence/_das-index.md) — Measurements with their build and date, and the stated limit on every claim. Contains: Claims; das, first run on a real corpus; Does this work have legs; Measurements; The reference measurement.
```

The skill's own description changed in the same way. Before:
`Reference documentation for corpus, sliced from /private/tmp/.../corpus. Covers: wizwit knowledge, architecture, brand, …`
After:
`Use for questions about Architecture, Brand, Career, Design, Evidence, Ideas, Kit, Offer, Operations, Who she is, Standards, Writing. The single source of truth for who she is, what she believes, how she builds and what she has done.`

8 of 98 rising to 98 of 98 on authored descriptions is the mechanism
`~/wizwit-knowledge/evidence/structure-over-tooling.md` section 3 identified: a generated
index is a rendering of the authored layer. The published build was rendering 8% of it.

## Two findings outside the comparison

1. **Neither build converts this corpus unattended.** The injection scan fires on two
   HTML comments, in `evidence/das-first-run.md` and
   `ideas/frameworks/documentation-as-skills.md`, both of which quote the Prisma payload
   as an example. A record of an injection is not an injection, the same class as the
   nineteen references in the reference measurement that must stay red on purpose. The
   new build has `--accept-scan-findings`; 0.2.0 requires an interactive confirm, so the
   published build cannot be scripted over a corpus that documents prompt injection.
   Both skills here were generated through a pty ([`instrument/drive-das.exp`](instrument/drive-das.exp))
   so the corpus stayed unmodified.

2. **The per-resource frame embeds an absolute local path**, once per file, 98 times:
   `> Reference material sliced from /private/tmp/.../corpus.` Run from a home directory
   that becomes `/Users/<name>/…`, and it reaches a committed team skill, which the docs
   site has a guide for.
