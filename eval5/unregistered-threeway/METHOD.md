One frozen task set run across four conditions over one corpus, measuring how much
documentation each route pulls into context and whether the answer is right. Every
number in [`results.md`](results.md) carries the command that produced it.

This is the fifth independent attempt at the das-against-search comparison. The four
before it are `../eval/`, `../eval2/`, `../eval3/`, `../eval4/` and
`~/wizwit-knowledge/evidence/structure-over-tooling.md`. **It is the first to compare two
das builds against each other**, which is the only comparison that isolates the index.

## The conditions

| Arm | Documentation reachable | Tools allowed | Route |
| --- | --- | --- | --- |
| **C** | none | Read, Grep, Glob | nothing to find, the control |
| **A** | the raw corpus at `./corpus` | Read, Grep, Glob | search |
| **E** | a skill generated by the new build | Read, Skill | the generated index |
| **F** | a skill generated by das 0.2.0 | Read, Skill | the generated index |

A and E both receive a pointer to whatever documentation they have, so the difference
between them is the route and not the presence of a hint. E and F open the prompt with
`/wizwit`, which loads the skill as a command before the task starts, so invocation is
not a variable and what remains is the cost of descending the index. Grep and Glob are
denied in E and F, so the index is the only route.

## Grading

Mechanical. Each question carries a list of OR-groups and every group must appear in the
answer, case-insensitive and whitespace-normalised. A refusal or a clarifying question
scores zero on every group regardless of what else it contains, which is the gate the
eval3 grader was missing when it gave vacuous passes to non-answers.

Ground truth was verified against the corpus before the set was frozen, with frontmatter
stripped from the source files first. That check caught three questions labelled
two-document that one file could answer, because every file's own frontmatter contains
the field names one of the questions asked for.

## Four isolation defects, each verified rather than assumed

Found while building this instrument. Each one would have invalidated the result.

1. **`claude -p` with `HOME` overridden is not isolated.** Project-instruction discovery
   walks "your working directory or any directory above it, other than your
   `~/.claude/CLAUDE.md`", ordered "from the filesystem root down to your working
   directory" (`code.claude.com/docs/en/memory`). Overriding `HOME` re-points `~`, so the
   real `~/.claude/CLAUDE.md` stops being the excluded user file and becomes an ordinary
   ancestor file for any working directory under the home directory. Canaries planted in
   each location leaked from four of six under `HOME` override alone. See
   [`instrument/probe-isolation.sh`](instrument/probe-isolation.sh).

2. **`--bare` and `--restricted` remove the mechanism under test.** `--bare` loads no
   skills at all and `--restricted` loads built-in skills but not `.claude/skills/`. So
   the flags that close defect 1 cannot be used in any arm that needs a project skill.
   Isolation here is structural instead: `env -i`, an empty per-trial `HOME`, and a trial
   root with no `CLAUDE.md` anywhere in its ancestor chain.

3. **`--allowed-tools` only pre-approves, it does not restrict.** A Bash call ran and
   echoed its marker under `--allowed-tools Read Grep Glob`. Bash was attempted in 8 of
   10 runs in the search arm and 2 of 10 in the index arm, so the arms were not
   tool-matched until every unwanted tool was denied explicitly.

4. **Overriding `HOME` does not restrict file access.** A trial globbed `/Users/**` and
   read files from the real home directory. A "no documentation" arm can therefore reach
   the corpus by absolute path, and an index-only arm can read the raw files and bypass
   its index. Path-scoped deny rules do block it, and **the absolute-path form needs a
   leading `//`**: `Read(/Users/**)` did not block the read and `Read(//Users/**)` did.

   The effect was large. Under containment the control arm's documentation tokens fell
   from 33,581 to 4,253, so the earlier figure was the control reading documentation from
   outside its trial.

Every run in `results.md` is preceded by a live containment assertion: a trial attempts
to read the real corpus and must answer `BLOCKED`, or the sweep refuses to start. A clean
sweep with no such control proves nothing about leakage.

## This bears on the earlier evidence

`~/wizwit-knowledge/evidence/structure-over-tooling.md` states that its index arm ran in
"an empty working directory, so nothing was greppable." Defect 4 says an empty working
directory does not prevent reading `~/wizwit-knowledge` by absolute path, and that study
used `claude -p` with `HOME` overridden and no path-scoped denies. Its runner was not
kept, so whether any arm actually reached outside its trial cannot be recovered.

This does not overturn that study. Its central finding is that varying the structure
moved four checks while varying the tool moved two of forty-three, and a leak would make
both arms stronger rather than one. It does mean the isolation sentence needs qualifying,
and that every future run states its containment control.

## Stated limits

- One corpus, which is her own, 98 files and about 105,000 tokens. Nothing here
  generalises to a corpus of a different size or a different authoring standard.
- Haiku only. Invocation and descent are model behaviours and this says nothing about
  larger models.
- Accuracy saturates. Every arm holding the documentation answers nearly everything
  correctly, so this instrument measures retrieval cost and cannot detect an accuracy
  difference between search and an index. A harder set or a corpus the model knows
  incorrectly is required for that, which is what `../eval4/` did and what the next study
  should repeat against the new build.
- Dollar cost is dominated by the cached system prompt, so it moves far less than
  documentation tokens do. Documentation tokens pulled into context is the metric that
  tracks the index.
- Two of ten questions require two documents. A genuinely multi-hop set was not authored,
  because the corpus's own cross-references mostly resolve within one file.

## Reproduce

```bash
cd eval5/instrument
./probe-isolation.sh                  # isolation canaries, ~$0.04
node study.mjs 1 C A E F              # one run per cell
node study.mjs 5 C A E F              # the sweep, 200 runs
node analyze.mjs                      # structural artifact diff, no API spend
```

`study.mjs` hard-codes the scratchpad paths it was built with. Point `SD` and `TRIAL_ROOT`
at a working directory and a trial root that are not inside each other before re-running,
or defect 4 reappears.
